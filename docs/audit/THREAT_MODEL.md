# Phase 1 Threat Model

Scope: current checked-in code, static review only. Confidence labels describe evidence strength, not exploitability proof.

| Threat | Evidence and impact | Confidence | Recommendation |
|---|---|---|---|
| Malicious page influences content-script inputs | `js/contentscript.js` inspects host DOM and sends state to the extension. No `window.postMessage` bridge or page-callable API was found. The worker receives `reportTabState` and `savePreviewData` paths without a universal `sender` check (`js/tgs.js:1617+`). | **Certain** no direct bridge; **Likely** compromised/hostile content can influence observed data. | Validate message sender/tab association, schemas and bounds; keep privileged actions narrow. |
| Other extension invokes external API | `js/tgs.js:1761-1814` accepts `suspend` / `unsuspend`, optional numeric tab id, and can target the active tab when omitted. It does not disclose URL/session contents. No sender-ID allowlist. | **Certain** behavior. | Remove external listener per owner decision or restrict to a documented trusted ID. |
| Hostile suspended hash / displayed values | URL generation concatenates raw `uri` into the fragment (`gsUtils.js:464-477`); title is decoded and sent to `innerHTML` (`suspended.js:194-197`); URL/reason also enter HTML sinks. Original URL is navigated on explicit unsuspend/link actions. | **Certain** unsafe HTML insertion; **Likely** crafted hash can cause script-capable markup in extension origin; **Guess** whether Chrome allows script execution or navigation to particular `javascript:`, `data:`, or `chrome://` targets without runtime testing. | Parse URL, allow only intended schemes, encode fragment fields separately, use safe DOM APIs; test hostile hashes in Chromium/Chrome for Testing. |
| Crafted foreign suspended page | `serviceWorker.js` startup migration reads foreign suspended URL hashes and rewrites matching tabs; parser checks presence of fields but does not enforce a safe origin/scheme for `uri`. | **Likely** unsafe trust boundary; runtime reachability not tested. | Remove migration or validate source extension/origin, hash schema and destination scheme. |
| Local attacker reads extension data | Local profile access can expose full URLs, titles, screenshots, favicon data and saved sessions in extension storage/IndexedDB. Backup `.txt` writes full URLs to Downloads. | **Certain** data placement; **Likely** exposure if profile/downloads are accessible. | Minimize, provide one-click wipe, explain local profile/cloud Downloads exposure, exclude incognito by design. |
| Incognito data persists | Sampler and backup do not filter `tab.incognito`; split mode scopes queries by process, but Chrome shares local/sync storage across incognito and regular contexts. | **Certain** missing explicit exclusion and shared storage rule; **Likely** that incognito URLs can enter persisted caches/backups; exact runtime path untested. | Explicitly skip incognito tabs before sampling, preview/session persistence and backup; test split mode. |
| Vendor supply chain / renderer resource access | Bundled renderers contain XHR/fetch paths for page-referenced images/fonts; `db.js` is a bundled IndexedDB wrapper with no version header. | **Certain** API presence; **Guess** about exact reachable resources without runtime trace. | Pin provenance/hash, inspect upstream versions and test blocked-network behavior. |
| Release/update path | Manifest has no `update_url`; project is distributed as local unpacked/release zip. | **Certain** from manifest and project policy. | Publish checksummed release artifacts and verify manually; no runtime auto-update exists. |

The audited source previously registered `runtime.onMessageExternal`, which accepts cross-extension messages when `externally_connectable` is omitted. Phase 2 task 2.11 removed that handler; current source has no external message listener. See [runtime messaging](https://developer.chrome.com/docs/extensions/reference/api/runtime) and [externally_connectable](https://developer.chrome.com/docs/extensions/reference/manifest/externally-connectable). No exploitability tests were run. This threat model does not claim sandbox bypass or execution of arbitrary JavaScript.
