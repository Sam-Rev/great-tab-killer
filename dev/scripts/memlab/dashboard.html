Процессы выбранного браузера

Память процесса = phys_footprint (как «Память» в Мониторинге системы). RSS — только то, что сейчас в RAM; разница — сжатое и вытесненное в swap.

Ручной A/B на вашем обычном Chrome

  1. Выберите браузер вверху справа. Ничего не трогайте и нажмите «Записать A»: идёт усреднение в течение окна.
  2. Сделайте действие (например, «усыпить все вкладки» через TGS).
  3. Нажмите «Записать B»: сначала ожидание стабилизации, потом такое же окно замера.

Пока идёт окно — не работайте в браузере: любое действие попадёт в замер. Для честного сравнения методов лучше «Автотест»: там одинаковые вкладки и чистый Chrome.

Что сравнить

Каждый прогон — отдельный чистый Chrome с временным профилем и этим расширением из репозитория. Ваш Chrome не затрагивается, но во время теста откроется ещё одно окно Chrome: не закрывайте его и не кликайте в нём.

Страницы для теста (одна на строку)

Больше вкладок — заметнее разница и меньше доля шума. 20–30 страниц — хороший баланс.

Откуда цифры

Все значения берутся из ядра macOS (proc_pid_rusage, sysctl, vm_stat), а не из Chrome и не из расширения. Это те же источники, что у «Мониторинга системы».

Память Chrome (phys_footprint)
Сумма «Памяти» всех процессов этого экземпляра Chrome, включая сжатую и вытесненную в swap. Общие страницы не задваиваются. Главная метрика «сколько Chrome отнимает у системы».
вкладки / расширения / GPU / browser / служебные
Разбивка по типам процессов. «Расширения» — процессы расширений: именно там живут все усыплённые вкладки TGS (suspended.html), поэтому их вес растёт с числом усыплённых вкладок.
CPU Chrome, %
Процессорное время всех процессов за интервал. 100% = одно ядро полностью. Точная сумма, а не мгновенная оценка.
Пробуждения CPU, /с
Сколько раз процессы будили процессор. Таймеры фоновых страниц. Влияет на батарею и на «Энергопотребление» в Мониторинге системы.
Энергия (индекс)
Счётчик энергии ядра. Абсолютные единицы не задокументированы — сравнивайте только между собой на одной машине.
Swap, сжатая память, свободно %, давление
Состояние всей системы. Они зависят от всего, что работает на Mac, поэтому шумные. Сами по себе не доказывают эффект, но показывают итог для системы.
Чтение из swap и распаковки, стр/с
Это и есть ощущаемые «тормоза»: система достаёт данные с диска или распаковывает их. Чем меньше, тем отзывчивее Mac.

Как читать результаты автотеста

  • Δ — «после минус до» внутри одного прогона (медиана по повторам). Отрицательное по памяти и CPU — хорошо.
  • Чистый эффект — Δ варианта минус Δ контроля. Контроль ничего не делает и показывает, насколько цифры «плывут» сами (догрузка страниц, сборка мусора). Сравнивайте варианты по этой цифре.
  • Разброс — минимум и максимум Δ по повторам. Если разброс больше разницы между вариантами — разницы нет, нужно больше повторов или вкладок.
  • «Закрыть вкладки» — предел: лучше этого никакое усыпление не сделает. Хороший метод должен приближаться к нему.
  • Сверяйте состояние вкладок после действия (раскройте прогон): если TGS усыпил не все вкладки, результат занижен.
